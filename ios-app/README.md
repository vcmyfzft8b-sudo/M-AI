# Memo AI iOS App

This folder is the separate iOS version of Memo AI. It is intentionally isolated from the web app package so native tooling, Xcode files, and StoreKit code can evolve without changing the normal web build.

## Structure

- `capacitor.config.ts` loads the canonical production app at `https://memoai.eu`.
- `ios/App` is the native Xcode project generated by Capacitor.
- `ios/App/App/MemoStoreKitPlugin.swift` exposes App Store purchase, restore, and product lookup methods to the web UI.
- `ios/App/App/PrivacyInfo.xcprivacy` declares the app-level privacy manifest for Apple tooling.
- `ios/App/App/Assets.xcassets` contains Memo-branded app icon and splash assets.
- `www` is the Capacitor fallback bundle. The release app uses the remote production URL, and `server.errorPath` shows the local fallback page only if the production app cannot load.

## Local Commands

```bash
npm install --prefix ios-app
npm run --prefix ios-app sync
npm run --prefix ios-app verify
npm run --prefix ios-app open
```

To test a local or preview server inside the iOS shell:

```bash
MEMO_IOS_SERVER_URL=http://localhost:3000 npm run --prefix ios-app sync
```

Use `https://memoai.eu` again before App Store or TestFlight builds.

## Required Apple Setup

1. Create the bundle ID `eu.memoai.app` in Apple Developer.
2. Enable In-App Purchase capability for the app target in Xcode.
3. Create auto-renewable subscription products in App Store Connect:
   - `eu.memoai.pro.monthly`
   - `eu.memoai.pro.yearly`
4. If product IDs change, update both:
   - `ios/App/App/Info.plist`
   - Vercel env vars `APPLE_IAP_MONTHLY_PRODUCT_ID` and `APPLE_IAP_YEARLY_PRODUCT_ID`
5. Configure Vercel production env vars for App Store transaction verification:
   - `APPLE_APP_STORE_ENVIRONMENT=production`
   - `APPLE_BUNDLE_ID=eu.memoai.app`
   - `APPLE_APP_APPLE_ID=<numeric App Store app id>`
   - `APPLE_ROOT_CERTIFICATES_BASE64=<comma-separated base64 DER Apple root certificates>`
6. Configure App Store Server Notifications in App Store Connect:
   - Production URL: `https://memoai.eu/api/billing/apple/notifications`
7. Add App Review test credentials and notes in App Store Connect.
8. Set App Store Connect support and privacy URLs:
   - Support URL: `https://memoai.eu/support`
   - Privacy Policy URL: `https://memoai.eu/legal/privacy`
9. Confirm email or Apple login works in the submitted iOS build. If Google login is enabled, do not submit a Google-only iOS login configuration.
10. Complete App Privacy nutrition labels for account email, uploaded files, audio, scans/photos, AI prompts, diagnostics, purchases, and any analytics actually enabled in production.
11. Reconcile the App Store Connect privacy labels with `ios/App/App/PrivacyInfo.xcprivacy`.
12. Run `npm run ios:verify` from the repo root before building the archive.
13. Follow `docs/xcode-archive-checklist.md` for signing, sandbox purchase testing, TestFlight upload, and App Review submission.

## App Store Review Notes

- The iOS shell appends `MemoAIiOS/1.0` to the user agent.
- That token switches the paywall from Stripe Checkout to App Store purchase.
- If `https://memoai.eu` cannot load, the native shell shows a branded local connection fallback instead of a blank WebView.
- StoreKit purchases include the Memo user UUID as the App Store `appAccountToken`.
- App Store Server Notifications should post to `/api/billing/apple/notifications`.
- The iOS paywall includes restore purchases.
- Settings opens Apple subscription management for native subscriptions.
- Settings includes account deletion.
- Support pages hide Stripe Checkout and promo-code instructions in the iOS shell.
- The public support URL used in App Store Connect is contact-only and must not include Stripe Checkout or promo-code instructions.
- The iOS auth UI hides Google if Google is the only enabled provider; keep email or Apple login enabled for review.
- Do not submit the iOS app while Stripe checkout is visible inside the iOS shell.
